# Карточки игроков

Сайт: https://hec1n.github.io/cards/ — отдельные карточки неко и человека, без мастерских секретов.

После первой игры: уклонение 2 у обоих; жестокость 2 и медитация 2 у человека. У неко 296 монет и 9 стрел, у человека 386 монет и 3 кинжала. Туники и начальное оружие сохранены. Атакующие способности ещё не изучены. Эффект жестокости пока определяет мастер. Портреты предоставлены пользователем.

## Общее сохранение

Supabase хранит ХП, экипировку, монеты и инвентарь. Навыки хранятся в cards.skills отдельно от обычного состояния и добавляются мастером прямо в карточке. Данные загружаются при открытии и проверяются каждые 5 секунд в видимой вкладке. Пока открыта форма экипировки, опрос приостанавливается, чтобы не смешивать черновик с новой версией.

Просмотр публичный, как у исходного сайта. Изменения доступны только вошедшему владельцу карточки и мастеру. Таблица card_editors содержит разрешённые адреса; она не публикуется в GitHub, пользователь видит только свои права. Функция save_card проверяет подтверждённый аккаунт, права на персонажа и ревизию. Прямые изменения таблиц из браузера запрещены. При конфликте загружается свежая карточка; запрос не повторяется автоматически.

Создание аккаунта: Supabase → Authentication → Users → Add user → Create new user. Мастер сам задаёт пароль, оставляет Auto confirm user и передаёт данные своему игроку. Это не требует почтовой рассылки. На сайте только вход. Самостоятельная регистрация не включена в интерфейс: штатный SMTP Supabase не отправляет письма произвольным игрокам. Пароли и секретные API-ключи нельзя помещать в исходники.

Добавление доступа через SQL Editor (заменить email):

    insert into public.card_editors(email,card_id)
    values ('player@example.com','neko') on conflict do nothing;

Для мастера добавить по записи с human и neko. Неко пока ожидает назначения почты. Аккаунт Supabase Dashboard и аккаунт карточек — разные аккаунты.

supabase-config.js содержит только публичные URL и publishable key. supabase/setup.sql — схема для новой базы и начальные снимки. Не запускать повторно поверх настроенной базы без проверки существующих политик. Общие данные не переинициализируются при сборке/деплое. Изменения после начала игры выполняются через карточки.

Локальные сохранения прежней версии остаются в браузере. Облачный режим использует отдельный кеш и никогда не загружает старую локальную карточку на сервер автоматически. Кеш не позволяет редактировать без подключения. Текущие ХП в базе оставлены равными последним известным 5; новых значений мастер не сообщал.

## Разработка

    node build.mjs
    node test-state.mjs
    node test-cloud.mjs

GitHub Pages: master, папка /. Файлы HTML, JS, CSS, assets, vendor и .nojekyll публикуются вместе. vendor/supabase.js — официальный UMD пакет @supabase/supabase-js 2.102.0.

ХП меняются от 0 до текущего максимума. Смена брони/оружия сохраняет величину ран и не поднимает персонажа с 0 ХП. Монеты не становятся отрицательными. Одинаковые предметы объединяются, «Убрать» удаляет строку целиком. Инвентарь не экипирует вещи автоматически.

## Навыки мастера

После setup.sql применяется supabase/skills.sql. Право can_manage_skills выдаётся мастеру на обе карточки в приватной таблице card_editors; адреса пользователей в репозиторий не включаются. Только это право открывает кнопку «Добавить навык» и RPC save_card_skills. Поля: название (80 символов), уровень 1–999, описание (1000 символов); дубликаты запрещены. Все добавленные навыки публичны для игроков. Тайные потенциалы в cards.skills не внесены. Обычный save_card не меняет столбец skills, включая сохранения из старых вкладок.
